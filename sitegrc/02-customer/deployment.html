Deployment & Configuration#

Configuration reference#

All gateway configuration is environment variables, centralised in gateway/src/config.ts.

Server#

VariableDefaultNotes
NODE_ENVdevelopmentSetting production turns authentication on and restricts CORS
PORT4100
HOST0.0.0.0
DATA_DIRdataHolds grcstudio.db and settings.json. Must be a persistent volume
LOG_LEVELdebug in dev, info in production

Security#

VariableDefaultNotes
JWT_SECRETa random 32-byte value per process⚠️ Must be set in production. Tokens do not survive a restart and are invalid across replicas without it
AUTH_ENABLEDtrue when NODE_ENV=productionSet true explicitly to enable JWT auth outside production
DEFAULT_PASSWORDgrcstudio123⚠️ Used by POST /api/auth/seed-passwords, which is unauthenticated — see the hardening checklist
SETTINGS_KEY(unset)When set, the stored Anthropic API key is AES-256-GCM encrypted at rest
PORTAL_ORIGINhttp://localhost:5273Added to the CORS allow-list. In production only the allow-list is accepted; in development any origin is

Rate limiting & request size#

VariableDefaultApplies to
RATE_LIMIT_GENERAL200 req/minEverything under /api/
RATE_LIMIT_HEAVY10 req/min/api/documents/:id/extract, /api/agent/run, /api/import
MAX_BODY_SIZE2mbJSON body cap

Limits are per process, not shared across replicas.

Retention#

VariableDefaultBounds
AUDIT_MAX_ENTRIES300Audit entries read back into state
DECISION_MAX_ENTRIES200Runtime decisions
SCAN_MAX_ENTRIES100Scan records

These bound what is loaded, not what is stored. Raise them for a longer evidence window.

Policy engine#

VariableDefaultNotes
OPA_SERVER_URL(unset)Use a persistent OPA server (e.g. http://opa:8181) instead of spawning the CLI. Avoids per-evaluation process spawn and event-loop blocking

Without it, the gateway looks for the opa binary at /opt/homebrew/bin/opa, /usr/local/bin/opa, then PATH. If none is found, the builtin evaluator is used and semantic consistency is reported as null.

LLM#

VariableDefaultNotes
ANTHROPIC_API_KEY(unset)Enables Claude extraction and the live agent runner
ANTHROPIC_API_KEY_SECRET_NAME(unset)GCP Secret Manager name — highest priority in the resolution order

Resolution order: GCP Secret Manager → settings.json → ANTHROPIC_API_KEY → .env. The portal writes to settings.json, so a key set in the UI overrides the environment.

Portal#

The portal is a Vite build; the dev server proxies /api to http://localhost:4100. For a production build, serve the static output behind a reverse proxy that routes /api to the gateway.

Running from source#

cd gateway && npm install && npm run dev    # tsx watch, :4100
cd portal  && npm install && npm run dev    # vite,      :5273

Useful scripts:

CommandDoes
npm run devWatch mode (tsx watch src/index.ts)
npm startRun once (tsx src/index.ts)
npm run scan -- <file>CLI scanner
npm run migrateMigrate a legacy JSON state.json into SQLite
npm testVitest — 87 tests
npm run typechecktsc --noEmit
npm run lint⚠️ Currently fails — see G3

This is the supported path today.

Docker#

docker-compose.yml declares two services:

ServiceBuildPortNotes
gateway./gateway4100Named volume for /app/data, healthcheck on /api/health, NODE_ENV=production
portal./portal5273Waits for gateway health

The gateway image is a two-stage Node 18 Alpine build that installs OPA v0.71.0, so the real engine is available in the container.

⚠️ docker compose up does not work as committed. Two defects:

  1. portal/Dockerfile does not exist, so the portal service cannot build (G1).
  2. The gateway image builds with npx tsc and starts node dist/index.js, but gateway/tsconfig.json sets "noEmit": true — dist/ is never produced (G2).

Both are small configuration fixes: add a portal Dockerfile, and give the build an emitting tsconfig (or run tsx in the container as the dev scripts do). Until then, run from source.

Note also that NODE_ENV=production in the compose file enables authentication, so a working image would additionally need JWT_SECRET set and passwords provisioned.

Production hardening checklist#

Ordered by consequence.

Before exposing the service to anyone

  • Disable or protect POST /api/auth/seed-passwords. It sits on the unauthenticated router, sets a known default password on every user lacking one, and returns that password in the response body. On a fresh deployment the three seeded users (compliance, security, AI-Ops) have no password — anyone who reaches the endpoint first obtains working credentials for all three (G5)
  • Set JWT_SECRET to a strong, stable value shared by every replica
  • Set DEFAULT_PASSWORD, or provision passwords out of band and never call the seed route
  • Confirm AUTH_ENABLED=true — verify with GET /api/health, which reports it
  • Set PORTAL_ORIGIN; confirm CORS is restricted (it is permissive outside production)
  • Terminate TLS in front of the gateway
  • Set SETTINGS_KEY so the Anthropic key is encrypted at rest, and confirm data/settings.json is mode 600

Data

  • Mount DATA_DIR on durable storage — grcstudio.db holds every bundle, decision, scan, waiver, and the audit chain
  • Back it up; SQLite in WAL mode needs .backup or a filesystem snapshot, not a plain file copy of a live database
  • Raise AUDIT_MAX_ENTRIES / DECISION_MAX_ENTRIES / SCAN_MAX_ENTRIES to match your evidence-retention policy, or export on a schedule
  • Verify the audit chain periodically: GET /api/audit/verify

Policy engine

  • Install OPA, or set OPA_SERVER_URL, so bundles publish a real semantic consistency score instead of null
  • Prefer OPA_SERVER_URL under load — CLI mode spawns a process and blocks the event loop for the duration of each evaluation (G6)
  • Decide the enginePreference deliberately and record it

Operations

  • Wire GET /api/health to your orchestrator (the compose healthcheck already does)
  • Re-register webhooks on every boot — registrations are in memory only (G8)
  • Fix the lint configuration so CI is green and actually gates merges (G3)

Scale

  • Run a single gateway instance. State is materialised whole and written back on save; two writers against one SQLite file will lose updates (G6)
  • Rate limits and webhook registrations are per process — a second replica doubles the effective limits and halves webhook delivery

Migration from the JSON store#

Earlier versions persisted to data/state.json. npm run migrate imports that file into SQLite. The ClaudeProjects/GRCStudio copy still carries a state.json and predates the SQLite store — treat AntiGravityProjects/GRCStudio as canonical.
