GCP Project & APIs

~5 minutes
# Create project (or use existing)
gcloud projects create agentshield-poc --name="AgentShield POC"
gcloud config set project agentshield-poc

# Enable required APIs
gcloud services enable \
  run.googleapis.com \
  sqladmin.googleapis.com \
  redis.googleapis.com \
  artifactregistry.googleapis.com \
  secretmanager.googleapis.com \
  cloudbuild.googleapis.com

# Set region
gcloud config set run/region us-central1
2

Database & Cache

~10 minutes
# Create Cloud SQL PostgreSQL instance
gcloud sql instances create agentshield-db \
  --database-version=POSTGRES_16 \
  --tier=db-custom-1-3840 \
  --region=us-central1 \
  --storage-size=10GB \
  --storage-type=SSD \
  --availability-type=zonal

# Create database and user
gcloud sql databases create agentshield --instance=agentshield-db
gcloud sql users create agentshield --instance=agentshield-db \
  --password="$(openssl rand -base64 24)"

# Create Memorystore Redis instance
gcloud redis instances create agentshield-redis \
  --size=1 --region=us-central1 --redis-version=redis_7_0

# Create VPC connector for Cloud Run → Cloud SQL / Redis
gcloud compute networks vpc-access connectors create agentshield-vpc \
  --region=us-central1 --range=10.8.0.0/28

Secrets

~3 minutes

4. Test Agent Design

We create 6 purpose-built test agents, each designed to trigger specific AgentShield governance features. Together they cover REST, MCP, and external (OpenAI-compatible) protocols.

🔄 Echo Agent
Echoes back any input. Baseline agent for policy, auth, and audit testing.
Protocol: REST Slug: echo-agent Purpose: Policy enforcement, auth, audit logging Complexity: Minimal
💰 Finance Agent
Returns mock financial data with configurable token usage in responses.
Protocol: REST (with usage object) Slug: finance-agent Purpose: Cost tracking, budget enforcement Reports: input/output tokens + model name
📞 Support Agent
Simulates customer support — intentionally returns PII and sensitive data.
Protocol: REST Slug: support-agent Purpose: Guardrails (PII, profanity, injection) Returns: Emails, SSNs, phone numbers in output
💻 Code Review MCP
MCP server that exposes code review tools (analyze, lint, security-scan).
Protocol: MCP (SSE transport) Slug: code-review-mcp Purpose: MCP protocol, tool listing, tool invocation Tools: analyze_code, lint, security_scan
🌤️ Weather MCP
MCP server providing weather data tools. Lightweight, good for health checks.
Protocol: MCP (SSE transport) Slug: weather-mcp Purpose: MCP health monitoring, workflow chaining Tools: get_weather, get_forecast
🧠 OpenAI Proxy
Proxies to a real OpenAI-compatible endpoint (or mock). Returns real usage data.
Protocol: REST (OpenAI-compatible) Slug: openai-proxy Purpose: Real LLM integration, cost estimation Auth: Bearer token (API key)

5. Test Agent Implementation

5.1 Echo Agent (REST) — agents/echo-agent/

The simplest possible agent — echoes back input. Used to test auth, policies, and audit in isolation.

// server.js — Echo Agent
const express = require('express');
const app = express();
app.use(express.json());

app.get('/health', (req, res) => res.json({ status: 'healthy' }));

app.post('/', (req, res) => {
  res.json({
    agent: 'echo-agent',
    message: `Echo: ${req.body.prompt || req.body.message || JSON.stringify(req.body)}`,
    timestamp: new Date().toISOString(),
    metadata: {
      received_headers: {
        forwarded_by: req.headers['x-forwarded-by'],
        auth: req.headers['authorization'] ? 'present' : 'absent'
      }
    }
  });
});

app.listen(process.env.PORT || 8080);

5.2 Finance Agent (REST + Usage) — agents/finance-agent/

Returns mock financial data with a usage object so AgentShield can track tokens/costs.

// server.js — Finance Agent
app.post('/', (req, res) => {
  const prompt = req.body.prompt || '';
  const inputTokens = Math.ceil(prompt.length / 4);  // ~4 chars per token
  const outputTokens = Math.floor(Math.random() * 500) + 100;

  res.json({
    agent: 'finance-agent',
    response: {
      summary: `Q2 2026 revenue: $${(Math.random() * 10 + 5).toFixed(1)}M`,
      recommendation: 'Increase allocation to AI R&D by 15%',
      confidence: 0.87
    },
    // AgentShield reads this for cost tracking!
    usage: {
      input_tokens: inputTokens,
      output_tokens: outputTokens,
      model_name: 'gpt-4o',        // triggers auto cost estimation
      cost_cents: 0                  // 0 = AgentShield will auto-calculate
    }
  });
});

5.4 Code Review MCP Server — agents/code-review-mcp/

A proper MCP server exposing 3 tools. Demonstrates MCP protocol support.

// server.js — MCP Server (using @modelcontextprotocol/sdk)
import { McpServer } from '@modelcontextprotocol/sdk/server/mcp.js';
import { SSEServerTransport } from '@modelcontextprotocol/sdk/server/sse.js';

const server = new McpServer({ name: "code-review", version: "1.0.0" });

server.tool("analyze_code",
  { code: { type: "string", description: "Source code to analyze" } },
  async ({ code }) => ({
    content: [{ type: "text", text: `Analysis: ${code.length} chars, 
      ${(code.match(/function/g) || []).length} functions found. 
      Complexity: ${code.length > 500 ? 'High' : 'Low'}. Score: 8.5/10` }]
  })
);

server.tool("lint",
  { code: { type: "string" } },
  async ({ code }) => ({
    content: [{ type: "text", text: `Lint: 0 errors, 2 warnings (unused var, missing semicolon)` }]
  })
);

server.tool("security_scan",
  { code: { type: "string" } },
  async ({ code }) => ({
    content: [{ type: "text", text: code.includes('eval(')
      ? `🔴 CRITICAL: eval() detected — potential code injection vulnerability`
      : `🟢 No security vulnerabilities detected` }]
  })
);

// Mount SSE transport on Express
app.get('/mcp/sse', async (req, res) => {
  const transport = new SSEServerTransport('/mcp/messages', res);
  await server.connect(transport);
});

8. Demo 2: Policy Engine Phase 2

Scenario 2.1 — Create ABAC policies
Prove: Role-based access control works on a per-agent basis
  1. Create policy: "Only users with role=engineer can access code-review-mcp"
  2. Create policy: "Deny finance-agent access for role=intern"
  3. Create an API key with role engineer — invoke code-review → allowed
  4. Create an API key with role intern — invoke code-review → 403 POLICY_DENIED
  5. Same intern API key — invoke echo-agent → allowed (no policy blocks it)
✅ 403 returned with clear policy name and denial reason. Audit log records the blocked attempt.
Scenario 2.2 — Policy playground
Prove: Admins can test policies before deployment
  1. Open Dashboard → Playground
  2. Simulate: user with role=analyst accessing finance-agent
  3. Verify the playground shows "ALLOWED" or "DENIED" with matching policy details

Scenario 2.4 — OPA/Rego policy export
