2. Customer Deployment Tiers

Different customers have different needs. We define three tiers that map to specific cloud architectures:

Starter
Small Teams / POC
1–10 agents, <1K requests/day, 1–5 users
  • Single-instance backend
  • Smallest managed DB (2 vCPU)
  • No Redis required
  • CDN-hosted dashboard
  • Minimal ops burden
  • Target: $50–$150/mo
Growth
Mid-Market / Scale
10–100 agents, 10K–100K req/day, 5–50 users
  • 2–4 backend replicas + LB
  • Managed DB with HA (4 vCPU)
  • Managed Redis cluster
  • CDN + WAF for dashboard
  • CI/CD pipeline
  • Target: $300–$800/mo
Enterprise
Large Org / Regulated
100+ agents, 1M+ req/day, 50+ users, compliance
  • Kubernetes (auto-scaling)
  • Multi-AZ DB + read replicas
  • Redis cluster with failover
  • VPC peering, private endpoints
  • HIPAA/SOX compliant infra
  • Target: $1,500–$5,000+/mo

6. Database Strategy

PostgreSQL is the single source of truth for AgentShield. The database handles agents, policies, budgets, audit logs, evaluation results, compliance samples, and settings. Choosing the right managed service is critical.

📊 Migration Considerations
AgentShield uses 5 migration files (001–005) with standard SQL DDL. All three managed PostgreSQL services support the same SQL dialect. Migrations run via npm run migrate which executes sequentially. No vendor-specific SQL extensions are used — 100% portable across clouds.

7. Dashboard Hosting Options

The AgentShield Dashboard is a static React SPA built with Vite. After running vite build, it produces a dist/ folder (~850 KB gzipped) that can be served from any static hosting service.

Option Provider Pros Cons Cost
S3 + CloudFront AWS Full control, WAF integration, cache invalidation API Manual HTTPS cert setup (ACM), more config than alternatives ~$2–$15/mo
Static Web Apps Azure Free tier, built-in CI/CD from GitHub, auto-SSL Limited WAF unless paired with Front Door $0–$10/mo
Firebase Hosting GCP Free tier (10 GB/mo), instant global CDN, deploy in 1 command Limited advanced caching controls $0–$5/mo
Cloud Storage + CDN GCP Full control, Cloud Armor WAF, Cloud CDN edge caching More setup than Firebase Hosting ~$3–$10/mo
Nginx sidecar Any Self-contained — dashboard + backend in one deployment No CDN, higher latency for distant users $0 (included)
💡 Recommendation
For Starter/Growth tiers, use the cloud-native static hosting (Firebase/Static Web Apps/S3+CloudFront). For Enterprise, bundle the dashboard as an Nginx container sidecar within the K8s cluster for security — everything stays inside the VPC with no public-facing static assets.

9. Scalability Patterns

9.1 Backend Horizontal Scaling

The AgentShield backend is fully stateless — all state lives in PostgreSQL and Redis. This enables seamless horizontal scaling:

Load LevelReplicasCPU/Memory EachScaling Trigger
Light (<1K req/day)10.5 vCPU / 1 GB—
Moderate (1K–50K req/day)2–41 vCPU / 2 GBCPU > 70% or request latency > 100ms
Heavy (50K–500K req/day)4–102 vCPU / 4 GBCPU > 60% or concurrent connections > 500
Massive (1M+ req/day)10–50+2 vCPU / 4 GBHPA with custom metrics (queue depth, p99 latency)

9.2 Database Scaling Strategy

StrategyWhen to UseHow
Vertical Scaling First response to load increase Increase instance size (e.g., t4g.medium → r6g.large). Most managed services support this with <5min downtime.
Read Replicas Read-heavy dashboards (audit log queries, analytics) Route read-only queries (GET endpoints, reports) to read replicas. Write queries go to primary. Supported on all 3 clouds.
Connection Pooling 20+ backend replicas PgBouncer sidecar, RDS Proxy, or Cloud SQL Auth Proxy. Multiplexes 100s of app connections to ~30 DB connections.
Table Partitioning Audit logs > 100M rows Partition audit_log table by month (range partition on created_at). Enables fast pruning and archival.
Archival Pipeline HIPAA 6-year retention Monthly job: export old audit partitions to S3/GCS (Parquet), drop partition. Query archive via Athena/BigQuery.

9.3 Redis Scaling

Redis is used for rate limiting and policy/budget caching. For most deployments, a single small instance is sufficient:

  • Starter: No Redis — in-memory rate limit map (acceptable for single instance)
  • Growth: 1 GB Basic/Standard managed Redis
  • Enterprise: 5+ GB with HA failover and optional clustering for >100K concurrent keys

10. Extensibility & Maintainability Roadmap

Architectural decisions made today should accommodate future growth. Here are the key extensibility patterns:

Extension PointCurrent StateFuture Growth Path
Gateway Language Node.js (Express) Go/Rust gateway for <1ms latency. Run alongside Node.js admin API. Container separation makes this seamless.
Policy Engine JS-simulated OPA Standalone OPA sidecar (WebAssembly-compiled policies). Deploy as K8s sidecar or ECS sidecar container.
Event Streaming Sync audit writes to PostgreSQL Apache Kafka / AWS Kinesis / Google Pub/Sub for async audit event pipeline. Enables real-time dashboards + SIEM integration.
Multi-tenancy Single-tenant Schema-per-tenant (PostgreSQL schemas) or DB-per-tenant. Row-level security (RLS) for shared-schema option.
Plugin System Hardcoded middleware chain Dynamic middleware loader. Plugins as npm packages or WASM modules. Customer-defined guardrail plugins.
API Versioning /api/v1/ Add /api/v2/ with breaking changes. API gateway layer routes by version header.
Observability OpenTelemetry (OTLP) Export spans to Jaeger, Datadog, Grafana Tempo, or cloud-native (X-Ray, Cloud Trace). Already instrumented.
Dashboard SSO JWT (custom auth) OIDC/SAML integration (Okta, Azure AD, Google Workspace). Managed via environment variables.
🔑 Key Maintainability Decisions
  • Container-first: All components are containerized. Migrations run as init containers or CLI commands — never auto-run on startup.
  • Environment-driven config: All settings are environment variables. Zero code changes needed between clouds.
  • Stateless backend: No local file storage or in-memory state. Horizontal scaling is trivial.
  • Standard PostgreSQL: No vendor extensions. 100% portable SQL across all managed services.
  • OpenTelemetry: Already instrumented. Plug in any OTLP-compatible collector.

⚠️ Cost Optimization Tips
  • Reserved instances: 1-year commitments reduce DB costs by 30–40% on all clouds.
  • Savings Plans (AWS): Compute Savings Plans cover ECS Fargate + Lambda at up to 66% discount.
  • Azure Hybrid Benefit: Existing Windows Server / SQL Server licenses reduce Azure costs significantly.
  • GCP CUDs: Committed Use Discounts are spend-based (not instance-locked) — most flexible across services.
  • Audit archival: Move audit logs >90 days old to cold storage (Glacier/Cool/Coldline) — 80% cheaper.

💡 The Golden Rule
Deploy to the customer's existing cloud. AgentShield is 100% portable — standard Docker containers, standard PostgreSQL, standard Redis. The customer should never switch clouds just for AgentShield. Meet them where they are.
