Data Model#

PostgreSQL 16. 34 tables created by 18 sequential migrations in agentshield/migrations/, applied automatically at API boot (src/db/migrate.js).

Migrations are idempotent from 002 onward (CREATE TABLE IF NOT EXISTS, ADD COLUMN IF NOT EXISTS, ON CONFLICT DO NOTHING). A migration failure at boot is logged as non-fatal — the service still starts, so check startup logs after deploying schema changes.

cost_records#

Per-invocation usage: trace_id, agent_id, workflow_id, user_id, input/output/total tokens, cost_cents, model_name, and is_estimated (migration 007). Indexed on user_id and recorded_at. Unbounded growth — plan retention.

model_pricing#

model_name, vendor, input_per_1m, output_per_1m, is_active. Cached in-process for 5 minutes. A model absent from this table produces a cost of 0.

compliance_rules#

framework, rule_id (unique), name, description, category, severity, is_enabled, is_builtin, evaluation_config JSONB, plus OSCAL columns (oscal_catalog_id, oscal_control_id, oscal_statement, oscal_guidance) from migration 015. Built-ins can be disabled but the service refuses to delete them.

compliance_checks#

A check run: status, rule counts, results JSONB, samples_used, sample_source (generated / uploaded / custom), run_by, timestamps.

agent_compliance#

Join table (migration 016). Semantics: a config with assigned agents applies only to those agents; a config with none applies to all.

oscal_catalogs#

Imported catalog metadata, referenced by rules created from it.

Audit table#

audit_log#

The only BIGSERIAL table — sequential, append-only.

ColumnNotes
trace_idUUID, the correlation key
event_typeapi_request, policy_enforcement, budget_enforcement, guardrail_violation, mcp_proxy_request, mcp_proxy_policy_denied

Immutability:

CREATE RULE audit_no_update AS ON UPDATE TO audit_log DO INSTEAD NOTHING;
CREATE RULE audit_no_delete AS ON DELETE TO audit_log DO INSTEAD NOTHING;

UPDATE and DELETE are silently discarded by PostgreSQL itself. Indexed on trace_id, recorded_at, actor_id, outcome. Unbounded growth — plan partitioning or archival.

Conventions & gotchas#

  1. UUID primary keys everywhere except audit_log (BIGSERIAL, for ordered append).
  2. JSONB for extensibility. Policy rules, guardrail configs, agent auth, capabilities, audit details, evaluation results, and settings values are all JSONB. New shapes need no migration — and get no schema validation.
  3. TIMESTAMPTZ throughout. Everything is timezone-aware.
  4. CHECK constraints as the type system. Enumerations live in constraints, not enum types — adding a value requires altering the constraint.
  5. BIGINT arrives as a string. pg returns bigint and numeric as JavaScript strings; cost/service.js uses parseInt/parseFloat on every budget value. Do the same in new code or comparisons will be lexicographic.
  6. Soft deletes. Agents deactivate; built-in compliance rules disable; budgets archive.
  7. Two tables grow without bound — audit_log and cost_records gain a row per request. compliance_samples grows with sampling rate and stores encrypted payloads. Retention is your responsibility.
