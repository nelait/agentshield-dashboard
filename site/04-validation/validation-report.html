Between the code and the existing in-repo documentation#

Both repositories already contain documentation (agentshield/docs/, agentshield-dashboard/docs/). This set was written independently and does not modify them. Two things are worth flagging for whoever maintains them:

  1. agentshield/docs/product/ is load-bearing. The documentation portal reads those Markdown files from disk at runtime, and .dockerignore carries a specific exception to ship them. Editing them changes what customers see; deleting them breaks the portal.
  2. Branding has drifted between the two repos. The dashboard README.md and landing page say "AI Sure"; the console UI, the backend, and the database say "AgentShield". See G1.

Confidence and limitations#

High confidence — everything mechanically extracted or read directly: route inventory, schema, configuration, middleware order and semantics, enforcement thresholds, error codes, encryption, authentication.

Medium confidence — behavioural descriptions of paths not executed during this review: the Rego compilation path (requires the opa binary), OSCAL import/export against a real NIST catalog, the evaluation judge against a live LLM connection, and the GCP deployment scripts against a real project. These are described from code, not from observed runs.

Not assessed — runtime performance under load, the dashboard's visual behaviour (no browser session was run), dependency vulnerability status, and the correctness of the demo agents under agents/ and deploy/gcp/agents/.

Explicit scope boundary. No file in either source repository was created, modified, or deleted. The validator asserts this on every run.
