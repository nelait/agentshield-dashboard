Correctness defects#

G2 — Agent-scoped budgets violate the database constraint 🔴#

The console's budget form offers agent and workflow as scope types (agentshield-dashboard/src/pages/CostManagement.jsx:646), and costService.checkBudget() explicitly pushes an agent scope and queries for it (agentshield/src/cost/service.js:179-186). But the CHECK constraint permits only user, team, department, project, global (agentshield/migrations/001_initial_schema.sql:118), and no later migration alters it.

Effect. Creating an agent- or workflow-scoped budget from the UI raises a constraint violation, so agent-scoped budgets cannot exist — and the code path that checks them can never match. Per-agent spend caps are unavailable despite being offered.

Fix. A migration extending the constraint to include agent and workflow. The enforcement and increment logic (including slug matching) is already written.

G3 — Workflow-scoped policies never match 🟠#

_policyEnforcerCore declares let workflow = null; and never assigns it (agentshield/src/gateway/middleware/index.js), yet the evaluation context includes a workflow key and _evaluatePolicy reads context.workflow || context.agent for resource conditions.

Effect. A policy whose resources target a workflow slug evaluates against {} and never matches. Workflow runs are governed only by policies that match on user attributes or fall through to the default.

Fix. Resolve the workflow from req.params.workflowSlug in the middleware, the same way the agent is resolved.

G4 — Sub-cent costs round to zero 🟠#

estimateCost() returns Math.round(inputCost + outputCost) in whole cents (agentshield/src/cost/service.js:53).

Effect. Any single call costing under half a cent records 0. On low-price models or short prompts, cost-denominated budgets under-count indefinitely while token counts stay accurate.

Fix. Store cost in a higher-precision unit (micro-cents or NUMERIC), or accumulate fractional remainder per budget.

G7 — npm test cannot run ⚪#

package.json defines "test": "jest --config jest.config.js", but jest.config.js is not present in the repository. tests/unit/, tests/integration/, and tests/load/ are empty directories.

Coverage gaps in enforcement#

G5 — Outbound DLP covers one path only 🟠#

PII redaction of agent responses runs in POST /gateway/agents/:slug/invoke (agentshield/src/gateway/proxy.js). It does not run on workflow step outputs or on MCP tools/call results.

Effect. A caller can obtain unredacted output by routing through a workflow or the MCP proxy. For a strict egress boundary, restrict sensitive traffic to single-agent invokes, or add guardrail rules with scope: output.

G6 — tools/list is not policy-filtered 🟡#

The MCP proxy applies policy, guardrails, and budget to tools/call only (agentshield/src/gateway/mcp-proxy.js). tools/list is forwarded unmodified.

Effect. An MCP client discovers the upstream's full tool catalogue, including tools it is not permitted to invoke. Enforcement is correct — calls are blocked — but discovery leaks the shape of the tool surface.

G10 — Guardrails skip the workflow path 🟠#

guardrailEnforcer requires req.params.agentSlug and returns early without it (agentshield/src/gateway/middleware/index.js). Workflow runs carry workflowSlug, so no guardrail evaluation occurs — for the initial input or for any step.

G11 — Real-time content checks are regex-only 🟠#

Seven of the eight guardrail rule types are pattern matchers. The eighth, llm_judge, is explicitly skipped during live enforcement: "LLM judge skipped in real-time mode" (agentshield/src/guardrails/service.js).

Effect. Paraphrased or obfuscated prompt injection passes. The 15 built-in injection patterns catch literal, well-known phrasings only. Semantic evaluation exists but only in guardrail test runs and the Evaluation module.

G12 — Guardrails fail open 🟠#

_guardrailEnforcerCore catches any error and calls next() — the code comment states "Fail-open: don't block requests if guardrails service errors."

Effect. A guardrail service fault silently disables content enforcement while HTTP status codes stay healthy. This is a defensible availability trade-off, but it must be monitored: alert on the Guardrail enforcement error log line specifically, not on error rates.

G13 — The proxy governs only the traffic that reaches it 🟠#

Nothing prevents a client from calling a registered agent's endpoint_url directly.

Effect. Governance is a perimeter, not a capability restriction. Agents must be network-restricted to accept connections only from AgentShield, or the controls are advisory.

Compliance and evidence#

G14 — Retention is declared, not enforced 🟠#

compliance_configs.retention_days (default 2190) is stored and displayed, but no code deletes samples when it elapses. grep retention_days src/ finds only the insert and a rule evaluation.

Effect. Data accumulates past its stated retention. For GDPR in particular, over-retention is itself a violation. Implement purging in database maintenance.

G15 — Compliance rules attest controls; they do not verify behaviour 🟡#

Rule evaluation is a switch on rule.id performing regex checks (agentshield/src/compliance/service.js:359). Several rules return passed: true unconditionally — sox-3 "Access Logging Completeness" passes because the audit middleware exists; sox-5 "Approval Trail Verification" passes because the policy engine exists.

Effect. Legitimate as control attestation with supporting evidence. Not legitimate as proof the agent behaved correctly. Frame it accordingly with auditors.

G16 — The compliance encryption key cannot be rotated 🔴#

COMPLIANCE_ENCRYPTION_KEY is a single static value, scrypt-derived per operation with a fixed salt 'salt' (agentshield/src/compliance/service.js:159). There is no key versioning and no re-encryption path.

Effect. Changing the key makes every stored sample permanently undecryptable. There is no recovery from key loss.

Fix. Store a key id alongside each sample and support decrypting with historical keys.

Security posture#

G17 — CORS is unrestricted 🔴#

app.use(cors()) is mounted with no options (agentshield/src/index.js).

Effect. Any origin may call the API. Combined with the dashboard storing tokens in localStorage, this widens the blast radius of an XSS anywhere the token is reachable.

Fix. An origin allow-list driven by an env var.

G18 — Default credentials are published 🔴#

admin@agentshield.local / admin123 is seeded by migrations/001_initial_schema.sql and documented in both repos' READMEs and in .env.example.

Fix. Force a password change on first login, or generate a random password at provisioning and print it once.

G19 — Read access to governance config is not role-gated 🟠#

71 of 165 routes carry requireRole. The unguarded remainder includes GET /policies, GET /guardrails/profiles, GET /budgets, GET /audit, and GET /compliance/samples.

Effect. Any authenticated principal — including a viewer and any API key regardless of its scope array — can read the complete governance configuration and audit trail.

API key scopes are enforced on exactly one route: POST /api/v1/gateway/policy/check requires the policy:check scope (agentshield/src/gateway/proxy.js:384). Every other route ignores scopes entirely, so a key minted with ["policy:check"] can still invoke agents, read the audit log, and list every policy.

G20 — No MFA, SSO, or federated identity 🟠#

Authentication is local: bcrypt passwords and self-issued JWTs. No OIDC, SAML, or TOTP. Enterprise buyers with an SSO mandate will need an identity-aware proxy in front.

G21 — Session revocation does not invalidate live access tokens 🟡#

JWTs are stateless. Deleting a user_sessions row prevents refresh but does not stop an already-issued access token until its 15-minute expiry.

G22 — Rate limiting is per-instance and covers two endpoints 🟡#

express-rate-limit and rate-limit-redis are installed but unused. The only limiters are hand-rolled in-process Maps guarding the public demo-request and doc-access endpoints (agentshield/src/admin/routes.js:949). The gateway itself is not rate limited — only budgets constrain call volume, and only where budgets are configured.

Functional limits#

G8 — No automated test suite 🔴#

One test file exists (tests/yaml-parser.test.js, 24 cases). No CI configuration exists in either repository. Deployment validation is a shell script run against a live GCP environment (deploy/gcp/08-run-tests.sh).

Effect. Refactoring the middleware chain — the security model — has no safety net. This is the largest engineering risk in the codebase.

G9 — The workflow engine is minimal 🟠#

Sequential execution only: no parallel steps, no branching, no conditional routing, no retries, no compensation. workflow_agents.data_flow_rules is persisted but never applied — each step's output passes through whole. workflows.max_concurrent, daily_limit, and requires_approval are columns with no enforcement code.

G23 — Report scheduling is stored but never runs 🟠#

report_configs.schedule accepts daily/weekly/monthly and recipients holds an address list, but there is no scheduler and no mail sending anywhere in the codebase (node-cron is a declared dependency that is never required).

Effect. A user configuring a scheduled report gets no report.

G24 — Redis is provisioned but unused 🟡#

ioredis, redis, and rate-limit-redis are dependencies; Redis appears in docker-compose.yaml and in the GCP infrastructure script (Memorystore, ≈$35/month). No application code opens a connection — Redis appears in src/ only inside the OpenTelemetry instrumentation config.

Effect. ≈$35/month of unused infrastructure in the reference deployment, and no shared state across replicas.

G25 — Several dependencies are declared but unused ⚪#

joi, crypto-js, http-proxy-middleware, node-cron, express-rate-limit (backend) and react-router-dom (dashboard) are installed but never imported. Dead weight in install size and vulnerability surface.

G26 — Migrations run at boot with no lock 🟠#

src/index.js runs pending migrations on start, and failures are logged as non-fatal — the service starts anyway.

Effect. Concurrent instance startup can race on the same migration, and a failed migration produces a running instance against an out-of-date schema with no visible signal beyond a log line.

G27 — Single-tenant only 🟡#

One organisation per deployment. Roles scope permissions, not data — every authenticated user sees every agent, policy, and audit record. Multi-tenant isolation would require a tenant column on nearly every table.

Product and presentation#

G1 — Inconsistent product naming 🟠#

Three names are user-visible simultaneously:

SurfaceName shown
Dashboard sidebar, service logs, audit headersAgentShield
Landing page hero, dashboard READMEAI Sure (subtitle "by AgentShield")
Documentation portal"What is AI Sure?"
Production API domainapi.aisure.live
Repositories, package.json, database nameagentshield

Effect. A customer moving from the landing page to the console sees the product rename itself. Decide on one customer-facing name and align the console, the docs portal, and the email domains.

G28 — AWS and Azure deployments are unbuilt 🟡#

deploy/aws/ and deploy/azure/ contain README placeholders with no scripts. Only GCP is scripted and exercised. A buyer standardised on AWS is looking at unscoped porting work (the container itself has no GCP-specific dependency).
